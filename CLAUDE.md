# CLAUDE.md: REVERB // WORLDS

A static music player with 15 visual "worlds" and a music-reactive hologram, hosted on GitHub Pages at https://jowo66.github.io/reverb-worlds/. Plain HTML, CSS and ES modules: **no framework, no build step, no bundler, no image or audio assets.** Everything visual and the demo music is generated in code. (Deep Field's ship/robot forms are edge data baked from CC0 models by the offline tool `tools/bake_forms.py` and committed as JS; the owner approved this on 25 Oct 2026.) Keep it that way unless the owner explicitly asks otherwise.

Owner: Ejovwo Obahor (GitHub `Jowo66`). Background reading: `README.md` (features, setup, performance table).

## Commands

```bash
# Run locally. Serve the PARENT folder so the URL has the /reverb-worlds/ subpath, like GitHub Pages.
cd .. && python3 -m http.server 8765 --bind 127.0.0.1
# open http://127.0.0.1:8765/reverb-worlds/   (add ?sw=1 to enable the service worker locally)

# Tests (Python Playwright + Chromium: pip install playwright && python3 -m playwright install chromium)
# Run from the parent folder, with the server above running:
python3 reverb-worlds/tests/smoke_test.py        http://127.0.0.1:8765/reverb-worlds/   # 105 checks
python3 reverb-worlds/tests/spotify_mock_test.py http://127.0.0.1:8765/reverb-worlds/   # 41 checks, simulated Spotify
python3 reverb-worlds/tests/optimization_test.py http://127.0.0.1:8765/reverb-worlds/   # 24 checks
python3 reverb-worlds/tests/features_test.py     http://127.0.0.1:8765/reverb-worlds/   # 65 checks (v1.1, v1.2 share links + developer overlay, startup budget, Deep Field)
python -m unittest reverb-worlds/tests/test_bake_forms.py                         # 6 checks, model baking tool

# Syntax check one module quickly
node --check js/app.js
```

**Before every push: run all four suites; every check must pass.** For visual changes, also take screenshots of the affected worlds (desktop 1440×900 and mobile 390×844) and look at them: tests can't judge legibility.

Gotcha (Windows): with `core.autocrlf=true` files are checked out with CRLF and the startup budget reads ~4 KB too high; use `git config core.autocrlf input` in this clone. The smoke check "no JavaScript errors (desktop)" currently fails on `main` because the live Spotify embed script throws "no list was loaded" (external, since Oct 2026).

Gotcha: don't stop the test server with `pkill -f "http.server …"` inside a compound shell command. The pattern matches the shell's own command line and kills it. Stop it by PID instead.

## Deploy

Pushing to `main` runs `.github/workflows/pages.yml`. It copies only `index.html sw.js css js assets` into `_site`, stamps the commit SHA into `js/version.js` and `sw.js` (replacing `'dev'`), and deploys to Pages. Tests, docs and this file are not published. If a deploy fails with "No artifacts named github-pages", that is a transient GitHub issue: re-run the workflow.

## Architecture (where things live)

| Path | Role |
|---|---|
| `js/theme-registry.js` | The 15 worlds **as data** (palette, fonts, panel tokens, backdrop renderer, hologram forms/material/motion/transition/reactions/particles) |
| `js/theme-manager.js` | Applies a world (CSS variables + `data-theme`). **Must never call the player**, so switching worlds can't interrupt playback |
| `js/font-loader.js` | Classic `<head>` script: per-world Google Fonts map (`SPECS`, `WORLDS`). Loads only the active world's fonts and preloads neighbours |
| `js/world-packs.js` | `ensurePack(theme)`: worlds with `pack: '<id>'` keep their backdrop + forms in `js/worlds/<id>.js`, imported on first use (window and worker) and registered into `BACKDROPS`/`FORMS`. Returns `null` when nothing needs loading, so built-in worlds still switch synchronously. A failed load reverts the world switch with a toast |
| `js/worlds/deepfield.js`, `deepfield-baked.js` | Deep Field pack. `deepfield-baked.js` is generated by `tools/bake_forms.py` from `tools/forms-manifest.json`; never edit it by hand |
| `js/hologram/forms.js` | 113 built-in procedural forms. Each is built from paths and resampled to exactly N points so forms morph point-for-point |
| `js/hologram/hologram-engine.js` | Morphing, projection, materials, reactions, particles, drag-to-rotate, auto quality (`onSlow` turns panel blur off before reducing detail), throttling |
| `js/hologram/backdrops.js` | 14 animated backdrops: `init(S)` builds static layers, `draw(ctx,S,…)` animates. Also the `Backdrop` controller and thumbnail requests |
| `js/hologram/backdrop-worker.js` | Runs backdrop `init()` and draws thumbnails on `OffscreenCanvas`; thumbnails are cached per build. Main-thread fallback exists |
| `js/audio-analyser.js` | Real Web Audio analysis (page audio, mic, tab capture), approximate onset detection, `AmbientSource` + tap-tempo beat clock |
| `js/player/player-adapter.js` | `PlayerController`. Each provider declares `capabilities`, and the UI hides anything unsupported |
| `js/player/media-provider.js`, `demo-synth.js` | Built-in player: in-browser synthesised "REVERB Originals" (cached in Cache Storage per `SYNTH_VERSION`) and local files |
| `js/player/spotify-*.js` | Embed (iFrame API, docked in the player bar), Web Playback SDK, search, playlists, PKCE login, 404 device recovery |
| `js/player/lazy-provider.js` | Stand-in proxy so Spotify modules load on first use |
| `sw.js` | Offline cache: pre-caches a **hand-maintained list** of every shipped file, cache-first, update via "Reload" toast |
| `js/experience.js` | The **Experience** format (world, form, view, settings, source, tempo): `validate`, `capture`, `apply`, session storage, favourites. Experiences can only *lower* motion, never raise it |
| `js/features/*.js` | Lazy feature modules loaded via `loadFeature(name)` in `app.js`: `saved-panel` (Library › Saved, presets, saved list), `info-panel` (I key), `tour` (60-second tour), `share` (share links: encode/decode/open/copy; loaded only when a link is opened or copied), `dev-overlay` (D key or `?debug`: fps, backdrop ms, meters, onset ticks, worker, caches; removes its hooks on close), `spotify-ui` (Spotify search + playlist picker; loads when Sources opens or for signed-in users) |
| `js/app.js` | Wires everything; keyboard shortcuts; `window.__reverb` debug/test surface |

## Rules (keep these; they came from real decisions or bugs)

**Honesty and controls**
- Never fake audio sync. The stage chip must say what drives the visuals ("Audio reactive · …", "Beat clock · N BPM (tapped)", "Ambient animation"). Spotify audio is DRM-protected and can't be analysed; don't claim otherwise.
- No decorative controls. If a provider can't do something, hide the control; add capabilities to the provider, not just buttons.
- Onset detection is "approximate", not "beat tracking". Keep the wording.

**Spotify (verify against developer.spotify.com before changing; rules changed in Feb/Mar 2026)**
- Public client only: Authorization Code + PKCE. **Never add a client secret anywhere.** The tests scan for one. Tokens stay in `sessionStorage`.
- Development Mode: the app owner needs Premium; only allow-listed users can log in; `GET /search` max `limit=10` (page with `offset`); playlist field `tracks` was renamed `items` (support both).
- New Spotify-provider methods must also be added to the `methods:` list of the `lazyProvider(...)` call in `app.js`, or calls before load silently return `undefined`.
- The redirect URI is the site URL with `index.html` stripped. The same formula lives in `spotify-common.js` and in `app.js`; keep them identical.

**Performance and caching**
- **Adding or renaming any shipped file? Add it to `SHELL` in `sw.js`.** `optimization_test.py` fails if the list and the files disagree.
- Backdrop `init()` runs in a worker. It may only use `layer()` canvases and plain data, and must not touch `document`/`window`. `draw()` must only *read* layers (they arrive as `ImageBitmap`s).
- Change the synth or track definitions → bump `SYNTH_VERSION` in `demo-synth.js`, or old cached audio keeps playing.
- Fonts for a world must be in both `theme-registry.js` (CSS stack) and `font-loader.js` (`SPECS` + `WORLDS`).
- Throttled frames (`engine.maxFps`) must not feed auto-quality measurement.

**Accessibility**
- Respect `prefers-reduced-motion` (default motion = Reduced). In Reduced/Static modes: no glitch, tearing or inertia. Honour "Reduce flashing" and the minimum flash gap.
- Text, muted text, accent text and button text must pass the contrast checks in `smoke_test.py` for every world.
- Every control must be keyboard-reachable with a visible focus ring; icon-only buttons need `aria-label`; toggles use `aria-pressed` and a text state, not colour alone.

**Layout**
- Canvases are absolutely positioned inside their containers (a canvas in normal flow once made the mobile page 1,560 px wide). Grid children get `min-width: 0`.
- Third-party widgets live inside our layout (the Spotify embed is the compact 80 px player inside the player bar), never floating over content.

## Adding a world (checklist)

1. Add an entry to `THEMES` in `js/theme-registry.js` (unique `id`, `num`, palette passing contrast, fonts, panel, `background.renderer`, `hologram.*` with 8+ forms).
2. **Prefer a world pack** (the startup budget has ~1 KB left): set `pack: '<id>'` and put the backdrop (`backdrop = { init, draw }`, worker-safe `init`, read-only `draw`) and forms (`forms = { id: { label, build, upright? } }`) in `js/worlds/<id>.js`; add it to `SHELL` in `sw.js`. Forms traced from 3D models: add entries to `tools/forms-manifest.json` (CC0/redistributable licences only) and run `tools/bake_forms.py`. Only built-in worlds go straight into `js/hologram/forms.js` / `backdrops.js`.
3. Validate forms: no NaN, extent ≤ ~1.3, enough points/links, ≤ 140 paths (the low tier keeps 160).
4. Add its fonts to `js/font-loader.js`, and its ornament to `css/themes.css` (`[data-theme="<id>"]`).
5. Update counts in tests, the README, `index.html` (`#worlds-count` is static until a search) and the tour copy in `js/features/tour.js`.
6. Run all four suites and screenshot the new world on desktop and mobile.

## Roadmap

The plan for upcoming work is `docs/ROADMAP.md` (v2.0). Rules for working on it:
- Work **one release at a time, in the order of the roadmap's "Recommended order" table** (v1.1 first). Each release must be shippable on its own: tests green, deployed, reported.
- Build the **Experience format** (`js/experience.js`) first; Continue Session, Saved Experiences, Share links and Presets all depend on it.
- Owner decisions: **no community presets / no backend**, and **no visitor analytics, tracking or counters of any kind**. Don't propose them again.
- Add checks for every new feature to the relevant test suite and update the check counts in this file and the README.
- Respect the roadmap's budgets: startup JS/CSS ≤ 335 KB raw (lazy-load new features), backdrop ≤ 3 ms/frame, 60 fps target. The budget is measured by `features_test.py` from the files on disk that load at startup (JS + CSS, not HTML). After v1.1 it is **334.7 KB, so there is almost no headroom**: new startup code must be offset, and anything not needed for first paint goes into a `js/features/` module.
- v1.1 (Experience format, Continue Session, Favourites, Saved tab + presets, Info panel, Tour) is **done**. v1.2 is in progress: **Share links are done** (readable hash, e.g. `#world=ukiyo&form=moon-disc&i=61&rx=0.30&ry=1.20&src=reverb:tessellate&bpm=104`; every link goes through `validate`, can only lower motion, never autoplays, and wins over the saved session). The compact `#x=<base64url>` form from the roadmap was not built: the readable form already carries every Experience field. The **Developer Overlay is done** too. Still to do: World Personalities, Case Study page. Startup budget now: 334.0 KB after Deep Field (banner-comment padding was stripped across the startup files to make room; there is little left to strip, so new startup code must come out of real code).
- Each world's original art-direction brief lives in `docs/WORLDS.md` (not loaded at runtime).
- Flag anything that can't be verified locally (e.g. whether Spotify cover art can be exported to a canvas) instead of assuming.
